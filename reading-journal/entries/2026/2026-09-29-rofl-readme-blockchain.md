# 有人在 GitHub 的 README 里"挖矿"，已经挖出 558 个区块

💡 核心摘要

一个印度工程师在 GitHub 仓库的 README 文件里跑了一条"真"区块链：矿工在本地解题，把答案贴成 issue 评论，机器人验证后写进账本。它有 UTXO、有 ECDSA 签名、有难度调整、有减半——唯一没有的，是钱的价值。而这恰恰是它最值钱的地方：它把比特币的全部骨架拆下来给你看，还告诉你哪根骨头是假的。文末手把手教你今天就去挖一个区块。

> [!NOTE]
> **注解｜“真区块链”的准确边界**
>
> 更精确的说法是：ROFL 实现了许多 Bitcoin-like 数据结构与验证规则，但不是一个去中心化的点对点共识网络。其规范明确采用单一写入者、按提交顺序裁决、无分叉重组；所以它适合演示 UTXO、签名、PoW 与全链重放，却不能等同于比特币的开放网络安全模型。[项目 README](https://github.com/ram0verflow/ram0verflow#what-this-is)；[共识规范](https://github.com/ram0verflow/ram0verflow/blob/main/SPEC.md)

## 01 // 一个矿工，把项目作者的邮箱炸了

先讲一件最近在 Reddit 上炸锅的真人真事。

有个网名叫 kiddoreadit 的开发者，闲得发慌（科研级的那种发慌），做了一个项目叫 ROFL——一条迷你比特币，跑在 GitHub 仓库的 README 文件里。项目上线没几天，他打开邮箱，傻了：邮件像雪片一样飞来，全是系统通知——有人在挖矿，没日没夜地挖。

他跑到评论区问那位矿工："你就是那个挖矿的人吗？我的邮箱都被你的邮件淹没了，看来我的难度调整代码没用。"

对面回了一句特别凡尔赛的话：

"是的，我是在我的 VPS 上跑的。" —— 一位挂着 Security Engineer 头衔的矿工，顺便还提了个 PR 帮作者修难度调整的 bug。

此时此刻，这条链已经挖到 558 号区块，全网"市值"为零。挖得最狠的那位老哥，一个人占了 86.6% 的算力，账上有 15087 个 ROFL——一个永远不值钱、但他显然很快乐的数字。

评论区最高赞的玩笑是："兄弟就是 GitHub 宕机的罪魁祸首。"

另一条更妙："这就像在微波炉上玩《毁灭战士》——它原本不是设计用来这样用的，但该死，它居然真的管用。"

你可能觉得这就是个程序员梗。但你往下读十分钟会发现：这个玩笑项目，可能是普通人理解比特币最好的一本"活的教科书"——因为它把比特币的每一根骨头都拆出来摆在明面上，包括那些教科书从来不好意思细讲的。

> [!NOTE]
> **注解｜轶事与统计的证据层级**
>
> 仓库本身可以验证链上高度、矿工榜和余额，但这里的 Reddit 对话、职业头衔以及“导致 GitHub 宕机”均属于文章转述或玩笑，不能由账本数据推出。当前 README 已显示数千个区块且矿工分布明显变化，也说明这些数字应带上观测日期。[仓库动态账本](https://github.com/ram0verflow/ram0verflow)

## 02 // 原理：一条区块链的"器官移植手术"

先看 ROFL 怎么把比特币的五脏六腑搬进 GitHub。整个项目里有句话写得极狂：

"Everything here is real except the money."（这里的一切都是真的，除了钱。）

先说移植了什么真家伙：

- UTXO 模型：

每个币都是"未花费的输出"，花钱就是签名销毁旧的、生成新的——和比特币一模一样。

- secp256k1 签名：

用的和比特币同一条椭圆曲线，连 RFC 6979 确定性随机数、low-s 规范这种"处女座级"细节都没偷懒。整个加密库是作者用纯 Python 标准库手写的。

- 难度调整：

每 16 个区块根据实际出块时间重定难度，上下限钳制四倍——比特币 2016 区块窗口的缩小版。

- 减半机制：

初始奖励 50 ROFL，每 210 个区块减半。没错，矿工们正在为一个 71 个区块后就要腰斩的薪水疯狂加班。

- Coinbase 成熟期：

挖出来的币要等 10 个确认才能花。防止你挖完就跑。

> [!NOTE]
> **注解｜实现核验与两处措辞修正**
>
> 项目 README 确认了 UTXO、secp256k1、RFC 6979、low-s、16 区块调难、四倍钳制、210 区块减半和 10 确认成熟期。两点需要限定：UTXO 不是“每个币”，而是交易输出；coinbase maturity 主要限制新铸造输出过早花费，并非一般意义的“防止矿工挖完就跑”。[项目 README](https://github.com/ram0verflow/ram0verflow#what-this-is)；[Bitcoin 开发者参考：Transactions](https://developer.bitcoin.org/reference/transactions.html)

再说这套器官被移植到了怎样一个"身体"上。传统区块链的节点、网络、区块广播，在这里全部被 GitHub 的现成功能替代：

🗺️ GitHub 功能 → 区块链功能对照表

-

README 文件 → 官方账本（所有余额、区块、转账全在这页展示）

-

issue 评论 → 区块提交入口（挖到矿就贴一条评论）

-

GitHub Actions → 全节点（验证你的答案，合法就追加进 chain/blocks.jsonl）

-

pull request → 交易广播（转账可以走 PR，贡献还能挂在你主页上）

> [!NOTE]
> **注解｜README 是渲染视图，不是验证器的权威输入**
>
> 项目自称 canonical ledger 是 README，但验证脚本实际只读取 `chain/blocks.jsonl`，README 是由该文件渲染出的可读视图。GitHub Actions 也更接近受仓库所有者控制的验证与写入流水线，而非任何人都能独立参与的“全节点”。这一区分正是理解其信任模型的关键。[验证说明](https://github.com/ram0verflow/ram0verflow#verify-everything-yourself)；[`verify.py`](https://github.com/ram0verflow/ram0verflow/blob/main/verify.py)

最有意思的，是它唯一一处"明知故犯"的离经叛道：工作量证明不用哈希，用子集和谜题。

规则很朴素：给你 40 个数字和一个目标数，找出一个子集，加起来恰好等于目标。验证答案只需一次循环加法；求解要靠"中间相遇法"，2 的 20 次方的时间和内存。难度上升时，谜题不变大，只变多——一个区块从 1 道题起步，出块要压到十分钟，大约要 340 道。

为什么要这么干？作者的原话是：没有任何公司给子集和问题造出过 ASIC。比特币的算力战争是硬件的战争，而 ROFL 的算力战争是算法的战争——它自带的参考解法是故意写得很笨的，"打败它就是这项运动的全部"。

还有个设计堪称点睛之笔：你的 GitHub 用户名是谜题的种子。意思是每个人的题都不一样。你偷看别人评论区晒的答案？没用，那道题只问过它的主人。你想抢别人的功劳？也没用，换个用户名题目就全变了，功亏一篑。

一个防女巫、防抄袭、防抢跑的机制，就这么朴素地长在"用户名"这个最普通的东西上。

> [!NOTE]
> **注解｜绑定身份不等于防女巫**
>
> 用户名作为种子能阻止把某个已解答案直接换名提交，也降低评论区复制和抢跑的价值；但它不阻止一个人创建或控制多个 GitHub 账号，因此不能称为严格的 Sybil resistance。项目还说明当前难度上限为 3000 道题；“约 340 道”是某个历史负载下的估计，不是协议常数。[项目 README](https://github.com/ram0verflow/ram0verflow#mine-a-block)

## 03 // 本质：中本聪从来没发明"不可篡改"

读到这你可能在想：一个玩笑项目，值得写一篇文章吗？

值得。因为 ROFL 干了一件所有区块链教材都不敢干的事：它诚实地承认了自己的软肋，并且写进了说明书。项目文档里白纸黑字列着它的三条"命门"：只有一个写入者，所以没有分叉处理；纯 Python 解法要吃 200MB 内存；以及最重要的一条——

"工作量证明让重写历史能被任何持有早期副本的人检测到，但它不能让重写历史变得不可能。这条链活在一个单独的仓库里，它的寿命就等于这个仓库的寿命。"

这句话，请细品。

大众对区块链最大的误解，是以为"上链了就不可篡改、永垂不朽"。但《韩非子》两千多年前就讲过一个道理：规矩的效力从来不来自规矩本身，而来自执行规矩的人。商鞅变法前先"徙木立信"——立的不是法，是"我说到做到"的预期。中子星般坚硬的从来不是数据结构，而是"足够多的人各自留了一份底稿，并且都愿意较真"这件事。

所以比特币真正防篡改的，不是 SHA-256 这个数学函数——数学函数谁都能算，包括想作恶的人。防篡改的是全球几万个节点各自硬盘上那份账本，加上"改了也白改、没人认"的社会性共识。密码学只是让"较真"的成本变得足够低：任何人跑一句 verify.py，就能从创世区块开始重放整条链，验每个哈希、每个签名、每道谜题。

ROFL 把这件事演示得明明白白：它的 README 会告诉你"别信我"，它的验证脚本只读原始账本文件，不信任任何缓存状态。作者的原文是——"如果我哪天重写历史，就是它抓住我。"

《道德经》说"信言不美，美言不信"。满世界喊"绝对不可篡改、永久上链"的项目营销页，不如这一个承认自己"命和仓库一样长"的开源玩具来得诚实。

区块链从来不是"不可篡改的技术"，
它是"篡改成本高于收益"的社会学。

> [!NOTE]
> **注解｜可检测、可拒绝与不可篡改是三件事**
>
> 这段抓住了 ROFL 最重要的教学点，但对比特币的概括略显单因果。哈希链使修改可检测；数字签名约束花费授权；PoW 与链选择规则提高重写成本；独立验证者决定是否接受候选历史。ROFL 的旧副本持有者能证明仓库历史被替换，却无法仅靠协议迫使唯一写入者恢复它。项目限制章节对此表述得很清楚。[ROFL limitations](https://github.com/ram0verflow/ram0verflow#limitations)；[Bitcoin 白皮书](https://bitcoin.org/bitcoin.pdf)

## 04 // 手把手教你：今天就去挖你人生第一个区块

看到这，如果你手痒了——恭喜，这是正常反应。下面是保姆级教程，全程只需要一台装了 Python 的电脑，零依赖、零安装、零费用，Python 3.9 以上自带标准库就够。

### 第一步：把项目克隆下来

你只需要打开终端（Windows 用 PowerShell，Mac 用终端），粘这一行命令：

# 把仓库克隆到本地并进入目录

git clone https://github.com/ram0verflow/ram0verflow.git rofl &&cd rofl

### 第二步：生成你的钱包

# 生成一对密钥，会在当前目录创建 rofl-wallet.json

python3 wallet.py new

跑完你会得到一个 rofl1... 开头的地址——恭喜，你拥有了人生第一个（一文不值的）链上地址。

### 第三步：挖矿，把你的 GitHub 用户名带上

# 把 YOUR_GITHUB_HANDLE 换成你的 GitHub 用户名

python3 miner.py --miner YOUR_GITHUB_HANDLE --message "gm"

它会开始一道一道地解题。起步难度下大约半分钟出块。挖好后终端会打印一行以 rofl-block-v1: 开头的内容——把这一整行复制，贴到项目仓库的区块 issue 评论区。GitHub Action 会自动验证，通过了就把你的区块追加进链，README 上的账本随之刷新。

恭喜，你此刻完成了一次完整的挖矿 → 提交 → 全网验证 → 上链。你在矿工榜上会有名字，你的地址里会躺着 12.5 个 ROFL。

> [!NOTE]
> **注解｜命令仍对，奖励数字已过期**
>
> 仓库当前仍给出相同的 clone、钱包和矿工命令，但奖励按每 210 区块减半；项目 README 在本次阅读时显示下一奖励约为 `0.00019073 ROFL`，远低于文中的 12.5。提交入口的 issue 编号也会滚动变化，应从 README 的 “Mine a block” 链接进入，不要依赖旧文章中的状态描述。[官方挖矿说明](https://github.com/ram0verflow/ram0verflow#mine-a-block)

### 场景 A：给朋友转一笔"链上巨款"

挖到币之后，你可以体验一把"链上转账"。你输入：

python3 wallet.py send --to rofl1xxxxx --amount 1.5 --memo "gg"

它返回一行 rofl-tx-v1: 的文本，你把它贴到 mempool issue 里。之后矿工打包你的交易，手续费归出块的人。一个精妙的细节：备注（memo）是签名覆盖的一部分，中途谁也改不了、删不掉——你给朋友留言"这是上次那顿饭钱"，这句话就是防篡改的。

### 场景 B：把它当"活的区块链教材"读

这可能是比挖矿更值钱的用法。你只需要跑一句：

# 从创世区块开始重放整条链，逐项验证

python3 verify.py

# 跑一遍"试图攻破这条链"的九种攻击测试

python3 tests/test_chain.py

后者特别好玩：它会先搭一条真链、花真币、签真名，然后自己扮演黑客，用九种方式攻击——篡改子集、伪造签名、偷抬 coinbase、双花、偷区块、凑数填充、错难度、删区块、旧 tip——然后断言每一种都被拒绝。整套跑下来几秒钟，这就是一次免费的区块链安全课。

而且它的代码组织得极其克制：加密库约几百行，共识规则约几百行，整个项目没有任何一行第三方依赖。想搞懂 UTXO 到底怎么花的？打开 consensus.py，它比任何比特币科普视频都直接。

> [!NOTE]
> **注解｜验证脚本的教育价值与边界**
>
> 项目说明确认 `verify.py` 会重算区块哈希、难度、Merkle root、签名、coinbase 与供给，测试也覆盖所列九类无效状态。但测试通过证明的是实现对这些预设攻击的拒绝行为，不是完整的安全审计，更不覆盖 GitHub 账户、Actions、分支保护或仓库所有权等控制面风险。[验证说明](https://github.com/ram0verflow/ram0verflow#verify-everything-yourself)；[测试目录](https://github.com/ram0verflow/ram0verflow/tree/main/tests)

### ⚠️ 避坑提示（必读）

- 钱包文件是明文私钥。rofl-wallet.json

里躺着裸奔的私钥，作者原话："别在任何重要的地方复用它。"任何让你复用助记词、私钥的"教学项目"都是雷区。

- 别用 GitHub Actions 去挖矿。

把挖矿脚本塞进 Actions 自动跑，等于用平台算力薅平台羊毛，封号风险自负。本地跑，体验才完整——作者自己都是用 cron 定时任务跑的。

- ROFL 永远不值钱。

这不是"早期机会"，这就是一场开源行为艺术。它的价值在你的认知里，不在 K 线图里。

> [!NOTE]
> **注解｜最重要的操作安全提示**
>
> 项目 README 明确说 `rofl-wallet.json` 保存明文私钥，且不得在任何重要场景复用。更稳妥的做法是为这个玩具项目生成完全独立的密钥，并把仓库、issue 评论和任何第三方脚本都视为公开且不可信的环境。[项目限制](https://github.com/ram0verflow/ram0verflow#limitations)

## 05 // 案例：86.6% 算力背后，一堂价值千亿的课

回到开头那位炸了作者邮箱的矿工。这条链目前 558 个区块，他一个人挖了 484 个，占比 86.6%。

如果是真比特币，这是要把所有持币人吓出心脏病的事——理论上 51% 算力意味着可以重组交易、双花提款。历史上真发生过：2018 年比特币黄金（BTG）遭 51% 攻击，交易所被双花卷走价值约 1800 万美元的币。

但 ROFL 淡定得很。因为它的规则里写着：单写入者、无重组、凭提交先后裁决。这也正是它能教给你的一课——同一种算力集中，在不同的系统设计里，意味完全不同的东西。比特币必须靠经济激励让攻击不划算（矿机造出来挖矿比作恶赚钱），ROFL 干脆用中心化写入换来了"婴儿床里的绝对安全"，然后坦白告诉你这是婴儿床。

> [!NOTE]
> **注解｜51% 能力并非“任意提款”**
>
> 多数算力可用于排斥或重组近期交易、对攻击者自己的付款实施双花，但不能伪造他人签名、凭空花费任意 UTXO 或改变全节点执行的货币规则。ROFL 则没有最长链竞争：唯一写入者按提交先后接受区块，因此矿工占比与比特币中的多数算力不是同一种控制权。所谓“绝对安全”也过强，因为单一仓库与写入流水线本身就是集中故障域。[Bitcoin 白皮书](https://bitcoin.org/bitcoin.pdf)；[ROFL 共识规范](https://github.com/ram0verflow/ram0verflow/blob/main/SPEC.md)

另一个耐人寻味的细节，是矿工榜上的 @eltociear——他的区块消息清一色是"gm - block 1 of 4""gm - block 2 of 4"。gm 是 crypto 圈的黑话，"good morning"，社区晨安仪式。一个人对着一个不值钱的玩具链，认认真真地按顺序留言打卡，像在晨跑，也像在上香。

还有那些写着"we are capable of joy, suffering, desire"（我们有喜悦、苦难与欲望的能力）的区块消息。在比特币和以太坊的真实区块里，人们刻下的是"Chancellor on brink of second bailout for banks"（财政大臣站在第二次救助银行的边缘）这种时代宣言；在这条玩具链上，刻下的是近乎哲学独白的短句。

技术会变，刻字的冲动不变。从甲骨到青铜，从石碑到竹简，从区块链到 GitHub README——人类就是有把想留下的句子，刻进当下最硬的介质里的本能。

## 06 // 未来：当"理解比特币"的成本降到一顿早饭时间

ROFL 的浏览器有个设计哲学值得所有产品经理抄作业：它没有后端。页面从仓库里拉取原始账本文件，在你的浏览器里把整条链重放一遍——每个哈希、每个默克尔根、每道谜题重新验算。你的余额、你的排名，存在你本地，"发给任何人的数据为零"。

更狠的是，这套浏览器里的共识规则是从 Python 逐行移植到 JavaScript 的，两边"逐位一致"。也就是说，作者给同一套规则写了两个独立实现互相对账——这是密码学界"多实现交叉验证"的老传统，用来抓实现层的漏洞。一个玩具项目，工程严谨度对齐了行业最正规的打法。

> [!NOTE]
> **注解｜“独立实现”的限定**
>
> README 确认浏览器没有应用后端，会拉取 `chain/blocks.jsonl` 并在本地重放，JS 规则是 Python 的直接移植且目标是逐位一致。这能发现语言移植或实现差异，但“同一作者/同一规范的直接 port”与由独立团队编写、独立审计的多实现仍有不同的共同模式故障风险。[官方 explorer 说明](https://github.com/ram0verflow/ram0verflow#the-explorer)

那这事跟普通人有什么关系？关系大了。

过去十年，"区块链"这三个字在大众认知里走了一条奇怪的路：先是神化（暴富神话），然后是妖魔化（骗局、割韭菜），始终没变的是理解门槛。大多数人对比特币的全部认知，停留在"一个涨跌很吓人的东西"。而每次泡沫破裂时被收割的，恰恰是那些不懂原理只懂 K 线的人。

《孙子兵法》讲"知彼知己，百战不殆"，但它的前半句常被忽略："不知彼而知己，一胜一负；不知彼不知己，每战必殆。"在加密世界里，"彼"就是共识机器本身。你不需要会写代码，但你需要知道：签名花的是你自己的币、私钥丢了谁也救不了你、51% 攻击到底能干什么不能干什么。这些认知，是你在任何一轮牛熊里最硬的护城河。

而 ROFL 把获得这套认知的成本，压到了"会复制粘贴终端命令"的程度。半小时，一次真实完整的挖矿体验，胜过一百篇"三分钟看懂区块链"的营销号水文。这不是比喻，是你亲手验过的每一个签名。

往远了看一眼。当"在 README 里跑一条链"这种事成为可能，意味着基础设施的颗粒度已经细到了荒谬的程度。今天有人在 README 里跑区块链，明天就有人在表单里跑银行、在网盘里跑国家。工具的极限不断后退，剩下的问题永远是那个最古老的：拿它做什么？以及——谁说了算？

ROFL 自己的回答写在文档的最后一行，朴素得近乎抒情："ROFL 币一文不值，并且永远一文不值。"

一群明白人，用一堆不值钱的数字，玩明白了最值钱的事。

真正的共识从来不在代码里，
在愿意一起较真的人心里。

> **注解｜结论**
>
> ROFL 最适合作为“验证规则如何组合”的可执行教材：它让读者亲手观察 UTXO、签名、Merkle root、难度、奖励和无效状态拒绝。它也刻意暴露了缺失的部分——开放节点发现、分叉选择、去中心化写入和经济价值。正因为这条边界清楚，它比把“区块链”当成不可篡改魔法的演示更有教学价值。
